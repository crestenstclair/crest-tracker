# Piano Roll — controller editing and deferred recording

## Current design review — 16 October 2026

The [KORG Gadget study in Figma](https://www.figma.com/design/mvRQEFZc5Oi2ZbRkoHhXjH/Crest-Tracker?node-id=2174-6040) contains ten editable 1280 × 800 screens, T59–T68, plus research, source links and an attributed official screenshot. The user approved this editing direction. The shared native renderer now implements these editing states, replacing T57's full-page action list with the roll, bottom controls and compact side panels. Production-projection visual checks and event-driven application/DSP witnesses cover the editing workflow; physical controller acceptance remains a separate check. Recording setup remains deferred; the recording contract below is retained for future work. Expanded view and the minimap are excluded.

The primary references are the [official Switch manual and screenshot](https://www.detune.co.jp/KORG_Gadget_User_Manual_en.html), the [Gadget 3 Studio Guide](https://korguser.net/gadget/manual/studioguide/Gadget_SG_E1.pdf) (pages 22, 27 and 39–44), and [KORG's note-editing guide](https://support.korguser.net/hc/en-us/articles/115001289063-Editing-notes). The design adopts a dominant roll, visible piano keys, continuous duration bars, a time-aligned velocity lane and contextual editing. KORG's physical button assignments are reference material; Crest's configured semantic roles remain authoritative.

### Four independent timing controls

| Control | Changes | Does not change |
|---|---|---|
| Step Grid | Cursor step, visual subdivisions and placement of newly inserted notes | Existing onsets/durations, phrase execution division |
| New Length | Default duration for future inserted notes | Selected or existing notes |
| Selected Length | Duration of the selected notes; rhythmic or exact fractional beats | Their starts or the New Length default |
| Quantize Grid | Target spacing for the pending quantize operation | Edit grid, insertion defaults, or notes before Apply |

Step Grid and Quantize share 1/4, 1/8, 1/16, 1/32 and 1/64 values, with Straight/Triplet selection. Length uses the same values plus whole/half notes and exact beat fractions. A triplet lasts two-thirds of its straight counterpart: 1/4T = 2/3 quarter-note beat, 1/8T = 1/3, 1/16T = 1/6, 1/32T = 1/12, and 1/64T = 1/24. The picker displays both notation and beat duration.

### Editing and quantize flow

The roll retains its selected notes, exact cursor and viewport while a right-hand panel is open. Editing tools sit below the roll. West/Square (keyboard `[`) opens Tools, which exposes Grid, Defaults, View, selected-note editing, Velocity, Copy/Cut/Paste/Duplicate, Quantize, Note Off, Delete, Expression/FX, selection, Undo and Redo. Every bottom control has a controller path through this panel. Blank time/pitch cells stay reachable; holding navigation scans. Selecting an occupied cell never silently deletes a note.

The inspector exposes Pitch, Start, Length, Velocity, Release and Target. New-note velocity is separately labeled and affects future notes only. Velocity uses raw MIDI values 1–127, with fine ±1 and coarse ±10 adjustments. Pitch fields use semitone and octave increments. Note Off explicitly ends the targeted sounding note at the cursor; it is unavailable when no eligible note exists or the resulting duration would be non-positive. Delete removes the note instead.

Quantize opens with an explicit selected-note count and a preview. Starts is enabled and Lengths disabled by default. Solid cyan notes show the result; amber outlines show prior timing. Grid choices use a dedicated Quantize Grid picker, so choosing them cannot alter Step Grid. Selected is unavailable without a selection; All Notes requires an explicit scope change. Apply commits one transaction and returns focus to the roll; Cancel restores the original data. One Undo restores exact starts, durations and expression. The integrity rules below continue to apply.

Bottom-right hints describe the current grid, picker, field, lane or dialog. D-pad navigates; Edit activates; numeric adjustment hints specify both fine and coarse directions. Shift+Down returns from details to their parent and opens Main Menu from the roll. Shift+Up opens phrase settings from the roll. North/Start controls transport. The shipped UI must substitute actual configured button labels for semantic roles, including Fine and Range.

The Figma prototype links review states; it does not execute musical edits. Changing rhythmic tabs, applying a note edit or playing audio requires the future application implementation. Existing source screens remain intact for comparison.

## Deferred recording contract

15 October 2026. Piano Roll is the fifth phrase type, alongside Tracker, Drum Machine, Euclidean and Randomizer. This is the design/implementation contract. The repository now contains the pure capture/playback core and native Tracker host; README.md records implemented behavior and remaining native/hardware gates. Recording external MIDI/MPE performances while the Song plays is the primary outcome. The user confirmed that priority, routing to channels/instruments, gamepad editing, nudging and grid quantize. The editing behavior above is implemented; the recording defaults and capability gates below remain deferred design contracts.

## Record a performance

1. Open a phrase and choose **Type → Piano Roll**. Set its musical length; the roll shows pitch vertically and musical time horizontally. Song/Chain references and the three phrase FX slots remain available.
2. Open **Record setup**. Choose a connected input, ordinary MIDI channels or an MPE zone, destination and Monitor On/Off. Show input activity, the input master/member channels, pitch-bend ranges and destination capability. Resolve Make Unique/Edit Shared before arming a shared phrase.
3. **Arm** the selected phrase occurrence. Arming alone does not capture. **Record** from stopped starts playback and capture at the phrase start; during playback it waits for that occurrence's next loop start. Show Waiting/Recording distinctly. No count-in is the initial default.
4. Jam over the existing arrangement. Capture original timestamps and values, including out-of-scale notes and off-grid attacks. Monitoring sends each accepted input once through the sound boundary. Recorded playback must not double the still-monitored take.
5. **End take** stops capture, closes held recorded notes and commits one undoable take while accompaniment continues. **Stop** ends capture and transport. Listen on the next eligible phrase loop, then nudge, quantize or undo the take. Save the Song to retain it.

Initial workflow: one armed phrase occurrence, fixed-length loop, non-destructive overdub. Recording does not replace existing notes. Each pass gets fresh event identities. A take may contain multiple passes; End take commits them together. Previously committed content continues playing while capture is active; the current take is a visible draft, first replayed after commit at a future loop boundary beyond the delivered output horizon. This prevents duplicate monitoring without a second playback engine. Replace takes, comp lanes and automatic phrase growth are not required for this first slice.

Arming is explicit and remains bound to the chosen occurrence when editor focus changes. The recording scope loops that occurrence while the other tracks continue their own arrangement cursors. If the selected path is removed or its playback leaves that loop, end capture at that boundary. Stop/Seek, document replacement, input loss or capture overflow also end capture visibly; keep captured material recoverable. Do not silently rearm on reconnect. Source, route, MPE zone, phrase length and timing changes require ending the take first. Editing other phrases remains available.

## Capture and routing contract

- MIDI device/performance input is separate from gamepad or MIDI control-surface commands. An input packet carries endpoint/session identity, monotonic timestamp and sequence order. Record only explicitly selected external inputs; output/monitor traffic never loops back into capture by default.
- Convert hardware timestamps through the transport's tempo segments into rational quarter-note beats. Preserve within-loop onset plus unwrapped duration and pass identity. Sampling resolution comes from the clock, not the display grid. A tempo change must not retroactively retime earlier input. External sync requires a proven clock adapter; internal transport recording ships first.
- Keep MIDI note-on velocity 1–127, note-off velocity 0–127, CC/pressure 0–127 and pitch bend 0–16383 exactly. Percentages are display/edit units; opening or saving an untouched take never round-trips values through percentages. Note On velocity zero means Note Off. Unsupported MIDI/SysEx is reported, not advertised as captured. MIDI 2.0 and arbitrary SysEx recording are outside this first MIDI 1.0/MPE slice.
- Ordinary capture retains channel pitch bend, channel pressure, polyphonic key pressure, CC (including sustain), and program changes where supported. Channel-wide controls stay channel-wide; do not pretend a shared-channel bend is per-note expression. RPN/NRPN sequences retain order and destination, with MPE configuration interpreted separately by the adapter.
- MPE capture retains source endpoint, zone, master/member channels, note identity, attack/release velocity, per-note bend, channel pressure and CC74 timbre. Retain master-channel expression and sustain separately from member expression. Capture initial controller state at take/note entry, so held bend/pressure/CC74 does not vanish when no new packet arrives after the attack. Persist member/master bend-range and zone configuration; unknown configuration must be shown and resolved before claiming faithful MPE replay.
- Record setup contains a visible input-channel/zone → destination mapping. The simple default is one mapping for the chosen input zone; ordinary multichannel input may map channel groups separately. Each captured note/control stores its explicit target. This is an input stamping rule, not a hidden Track route or a phrase-settings instrument field. Changing the setup never reroutes existing notes. Selected-note target editing changes those events and their associated expression together.
- Destinations are a specific instrument, an endpoint plus fixed MIDI channel, or an endpoint plus MPE zone. A fixed channel supports ordinary MIDI; MPE requires an MPE-capable instrument/zone. Do not silently flatten independent expression onto one channel. A deliberately chosen conversion to ordinary MIDI must preview lost dimensions; it is not part of default routing.
- Preserve source channels as provenance. Playback can allocate different destination member channels to prevent collisions with accompaniment, concurrent phrase occurrences and monitoring. One destination allocator reserves member channels across those producers; never let one occurrence's bend, sustain or cleanup affect another. Independent master-channel expression/sustain timelines cannot safely share a zone: require distinct zones/endpoints (or a proven destination profile that isolates them) and reject conflicting routes before arming. Member-channel allocation alone does not isolate master messages. Reject a conflicting zone or exhausted allocation visibly instead of stealing an active member silently. Release an allocation only after its owned note and sustain lifecycle end, according to the destination's release contract.
- Match notes by source session/channel/pitch and an attack identity, not pitch alone. Different member channels can play the same pitch independently. MIDI 1.0 same-channel/same-pitch overlap is ambiguous: end the older owned attack before accepting a retrigger and show that limitation. Internal stale scheduled releases cannot kill a later attack. External MIDI 1.0 has no attack ID on Note Off: use a documented FIFO pairing policy for repeated identical source tuples, including retired attacks, and flag ambiguous overlap rather than promising lossless disambiguation. Malformed packets and impossible zone changes fault the affected capture stream without corrupting committed music.

Sustain does not overwrite key-release time. Store the physical release and pedal events separately. Notes held across loop boundaries keep one identity and unwrapped duration, with a continuation mark in the roll; modulo-wrap only the onset for the committed loop. Expression remains attached across the boundary. At End take, close held keys at the end time and terminate owned pedal/monitor state. Cache configured initial channel/master controls at take start; future loop entry must restore that take state before its first event without resetting unrelated destinations. Input already held before capture begins remains monitor-only until a new attack; do not invent a missing attack. Source disconnect closes known attacks at the last trustworthy transport position and marks the take interrupted. Output disconnect cannot guarantee physical silence: stop new delivery, preserve data, and show endpoint loss.

## Roll and editing

The main screen puts **Arm / Record / End take**, source, target, monitor, recording status and loop length above the roll. Show separate edit cursor and playhead. Notes use pitch names, velocity shading and a visible target label on selection. A continuation mark identifies notes crossing the loop edge. Scale shading is guidance; captured pitches are never scale-corrected. A lower lane switches between Velocity, Bend, Pressure, Timbre, Sustain and other captured controls. MPE lanes follow the selected note; shared-channel/master controls visibly identify their wider scope.

The native time viewport starts at eight beats; Grid / view changes its width from a quarter beat to 64 beats. Previous/Next Beats move by half a window. Cursor movement and optional playback Follow reveal the appropriate window; zoom, scrolling and explicit cursor movement pause Follow. Cursor navigation reveals pitches when they leave the visible lanes; View also offers explicit octave scrolling without moving the cursor. These are presentation changes: notes, their exact timestamps and the edit cursor survive zoom/scroll. The renderer bounds visual subdivisions to 64 cells while retaining exact note and cursor positions. Sustained notes remain visible after their attacks move offscreen, with continuation markers at window/phrase edges.

Editing operations are available from controller-navigable contextual panels. Expression shows a held-value trace aligned to the roll for the selected control lane, with explicit note/MPE-master scope, exact raw values, point navigation and Undo/Redo. Trace projection sorts a copy of the points, retains held values entering the viewport, and stops at the owned expression lifetime. Channel automation has its own explicit destination scope, phrase-time trace and point controls. Moving or deleting one channel point preserves notes and other controls in a mixed event. The recording workflow below remains deferred. Shortcuts accelerate the same commands; no mouse-only controls. Keep a visible focus ring, selected-note count, readable recording status beyond color, and shortcut help. Overlapping notes are individually reachable through Next/Previous note and a stacked-note chooser. Endpoint/instrument pickers and errors must also be reachable without a keyboard.

| Semantic control | Piano Roll behavior |
|---|---|
| D-pad / left stick | Move time/pitch cursor; navigate focused toolbar, menu or lane. |
| Select | Select note, confirm command, or insert a note in an empty cell. Selecting an occupied cell does not silently erase a take. |
| Edit + Left/Right | Nudge selected notes by one edit-grid unit. With Fine held, use 1/16 of that unit, displayed numerically. |
| West / Square (`[`) | Open the contextual note/selection menu. |
| Edit + Up/Down | Increase/decrease selected-note velocity by ten. |
| Right stick Left/Right | Resize selected notes by grid; Fine uses 1/16 grid. In a value field, adjust that field instead. |
| Right stick Up/Down | Adjust the focused Pitch, Velocity or expression value; Pitch moves by semitones for captured notes. Authored entry follows phrase pitch policy. |
| Range + D-pad | Extend rectangular time/pitch selection; Select all and target/channel filters also exist in the menu. |
| Back | Close popover/cancel draft and return focus. Never silently discard a recorded take. |
| Play | Toggle playback; stopping also finalizes active capture and releases owned notes. |
| Record action | Arm, start or end capture through toolbar/menu; ending capture can leave playback running. A hold-Play shortcut may be mapped, but must suppress its short-press action. |
| Shift + Up / Down / Left | Phrase settings / Main Menu / parent Chain; navigation does not redirect the armed occurrence. |
| Help | Show current bindings, including physical mappings for Edit, Fine, Range and Record. |

Crest retains its global physical roles: South is Edit, East is Shift, North is playback/preview, and Start controls transport in Tracker. Fine and Range use the configured bindings. KORG's A/B/X/Y/ZL/ZR assignments are research references, not a proposed replacement profile. Recording, when resumed, needs an explicit toolbar action rather than an undiscoverable hold gesture.

Context menu includes **Insert, Delete, Pitch, Start, Length, Velocity, Release velocity, Target, Select range/all, Copy, Paste, Duplicate, Quantize, Undo, Redo, Grid, Zoom, Scroll/follow, Expression and Record setup**. Edit exact start/duration through numeric fields as well as shortcuts. Expression point editing supports lane choice, previous/next point, add/delete point and time/value adjustment. Channel/master lanes require an explicit scope selection; deleting one note does not delete a pedal event shared by other notes. Three existing FX slots remain accessible in the selection/FX panel.

## Nudge, quantize and expression integrity

Grid choices reuse the existing quarter through 1/64 divisions and tuplet ratios. **Edit grid** is a visual/entry/snap setting, separate from phrase execution division and recorded precision. Changing it or zooming never moves existing notes. Do not reuse the existing division-retiming command for this control.

Nudge/quantize is one reversible transaction over stable selected note IDs. Move onset and note-relative expression together; preserve duration, release velocity and relative expression offsets. Quantize defaults to selected note starts only (nearest grid point; exact midpoint goes to the later point); **Quantize all** is explicit. Duration quantize is a separate option. Pitch quantize is not implied. Recording is unquantized by default; first slice needs post-record quantize, not destructive input snapping.

Example in quarter-note beats: on a 1/16 grid (1/4 beat), a note at 103/100 with duration 1/2 moves to beat 1. A bend at note-relative 1/10 remains 1/10 after its attack; duration stays 1/2. A +1 grid nudge moves that note to 5/4. Undo restores the exact original onset and all expression values.

Normal move/quantize clamps onset to valid grid positions inside [0, phraseLength); it never silently wraps a note to the next loop. Positive durations may cross the loop boundary. Resize changes the release boundary, not the expression timing scale: shortening trims note-relative points beyond the new supported lifetime and adds a terminal held value as needed; lengthening holds the last value. Undo restores removed points. Copy/duplicate copies note expression with fresh identities; delete removes only owned expression. Explicitly selected channel/master events move as their own events, never once per selected note. Retargeting notes with shared-channel expression must include that scope or reject with a clear explanation; no guessed per-note conversion.

## Ownership and persistence

Composition owns recorded notes, exact control values, note-relative expression and scoped channel/master events in common NoteData. Recording is transient application state: armed occurrence, source mapping, transport anchor, draft events, held input state and take ID. A bounded input adapter normalizes packets; pure capture transitions produce a draft; CommitTake validates expected phrase/reference revisions and atomically appends through Composition. A revision conflict preserves the take for retry/Save as new phrase; never overwrite a concurrent edit. Each committed take is one undo action.

Draft capture is marked unsaved immediately. Save during capture first finalizes the take at a defined timestamp, then saves an immutable Song revision. New/Open use the existing Save/Discard/Cancel guard for both committed edits and the draft; cancellation keeps capture/document state intact until the replacement is ready. Failed save/commit leaves the captured take recoverable. A bounded recoverable draft checkpoint is an implementation requirement before claiming crash-safe recording; ordinary Song saving does not serialize live device handles, armed state or allocation leases.

Playback uses the existing occurrence scheduler and FX pipeline. Note expression follows note transformations; probability suppression removes the note and its owned expression, timing FX move them together, and generated chord/retrigger voices get fresh runtime identities and independent member allocations. Unsupported expression/FX combinations fail compilation visibly while retaining the previous valid snapshot. Raw channel controls are not limited to three FX slots; they are recorded performance data. Stop, seek, panic, deletion, device loss and monitor-off release only owned notes and controls, with stale-output cancellation and no broad reset of unrelated accompaniment channels.

## Acceptance scenarios for implementation

1. Record off-grid E4 in C minor with velocity 101, release velocity 33 and pitch bend 12345. Reopen and replay without losing values or snapping timing/pitch. Grid and Notes/Intervals changes produce identical musical output.
2. Capture simultaneous identical pitches on two MPE members with different bend/pressure/CC74 curves plus master bend/sustain. Replay through validated MPE routing with no cross-note leakage, including initialized state before the first attack.
3. Record across a loop boundary and a tempo change while accompaniment plays. Keep one held-note identity and correct duration; current take is heard once through monitoring, committed take begins only at the eligible next loop. Existing notes survive overdubs and Undo take.
4. Complete setup, arm, record, end take, insert/delete, selection, nudge, pitch/length/velocity/release/target edits, copy/paste/duplicate, quantize, expression-point edits, undo/redo and zoom/scroll with gamepad only, including overlapping notes and error dialogs.
5. Apply the numeric quantize example above. Relative bend points move with their note. Copy/delete/resize/undo preserve ownership; shared sustain does not move once per note. Stale selection/revision commands reject atomically.
6. Run monitor and two occurrences against one MPE zone. Allocate members globally; reject saturation/conflicting master settings without stealing or resetting another owner. Fixed-channel MPE routing shows unsupported capability.
7. Stop/seek, input/output disconnect, monitor-off, buffer overflow, canceled New/Open, failed save and failed commit preserve recoverable captured material and owned cleanup. Reconnect never starts capture or replays stale Note On automatically.
8. Capture on a shared phrase after Make Unique/Edit Shared. Revalidate parent-chain references at commit. Song/Chain/Expanded/Minimap still reference the same source graph; view/type switching never bakes, flattens or drops expression.

## Reference and limits

[KORG Gadget for Nintendo Switch manual](https://www.detune.co.jp/KORG_Gadget_User_Manual_en.html), reviewed 15 October 2026: **Basic Controller Operation**, **Piano Roll Screen Operations**, **Play/Record Operations**. Verified inspiration: cursor navigation, A note entry with held length adjustment, right-stick length/velocity editing, ZR range selection, ZL grid-length adjustment, contextual menus, copy/paste, undo, triplet grid, Y playback/long-press recording and automation capture. The summary and detailed manual sections disagree on the range trigger; the detailed Piano Roll section specifies ZR. Crest's explicit Record action avoids relying on that ambiguity.

MPE ownership, routing, raw capture defaults, quantize semantics and safety rules above are Crest design proposals, not claims about KORG's MPE support. Do not inherit KORG's eight-bar clip limit. Synth's MPE reception, timestamps, pitch-range configuration and simultaneous monitor/playback allocation remain capability gates, not verified runtime features.
