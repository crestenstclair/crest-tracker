# Crest Tracker

Native macOS composition application built on the actual Crest Synth application, UI and audio renderer. Implementation is in progress; this is a runnable development build, not an M10 release.

## Run and develop

Keep `crest-tracker` and `crest-synth` as sibling checkouts. The current working Synth changes are required; the manifest's historical Git pin does not yet include the new host APIs.

Development checks require Rust, Python 3.11+ and Node.js 18+; CI uses Node.js 22 for the JavaScript checks.

```sh
make dev
make check-pair
make status-pair
make synth-inventory
make test
make test-host
make lint
make fmt-check
make workload
make audio-workload
make native-feedback
make bundle ARGS=--release
make verify-bundle
```

`make dev` compiles both working trees through an explicit Cargo path override. `make synth ARGS="..."` runs the original optimized Synth executable from its working checkout, retaining every standalone demo/diagnostic flag (for example, `--full-instrument-effect-demo`). `make synth-inventory` exports all canonical production instrument/effect schemas and validates their exact provider/preparer registrations; the current inventory contains 37 instruments and 39 effects. This inventory covers metadata and registration, not complete native feature parity. No publication or commit is needed to test Synth changes. `make diff-pair` shows both diffs. `make pin-synth REV=<published-40-character-SHA>` validates a published revision and updates the dependency; it never commits or pushes. `make check-pinned` intentionally excludes local overrides and is not yet a passing release gate.

Use `make bundle ARGS=--release` for optimized playback. It creates `target/release/Crest Tracker.app`, including Synth's resources and an ad-hoc signature. Plain `make bundle` creates an unoptimized debug package for development; callback performance targets require an optimized build. The builder stages a fresh bundle, rejects unresolved Git LFS resources, checks all resource hashes against both checkouts, verifies its signature and rejects non-system dynamic-library dependencies. A failed build preserves the previous generated app. `make verify-bundle BUNDLE="/path/to/Crest Tracker.app"` repeats those checks after relocation without rebuilding. These are local packages, not notarized releases.

## Controller navigation

The navigation contract is in [product-spec.md](product-spec.md#navigation) and [design/design-contracts.md](design/design-contracts.md#03--navigation--controller-contract). Shift+Right opens Song → Chain → Phrase; Shift+Left returns. Keep Shift held while moving between pages. Song Shift+Up opens Settings; Phrase Shift+Up opens Phrase Settings. Song Shift+Down opens Mixer; other views, including the integrated Synth, open Quick Jump. Shift+Back in Song opens the six-destination Main menu. Quick Jump includes Song File; its Shift+Up opens current Song settings. Up/Down browses these menus and Confirm activates the highlighted destination directly.

Tracker uses Synth's saved physical mappings. With defaults, Shift is left shoulder, Edit/confirm is the south face button, Back is left trigger, Confirm is right trigger, Play is Start, and Settings is the north face button. These describe physical positions; Switch and Xbox face labels differ. Existing preferences are not rewritten. Tapping Edit confirms; holding it with a direction edits. Releasing a used Edit chord never confirms again. Focus loss/disconnect still cancel held input. Controller settings remain Synth-owned.

The implementation-only “Controller actions” picker has been removed. Up above the first row/lane of a step grid focuses the actual toolbar; Up/Down traverses its visible controls, Confirm opens More Actions or activates a button, and Back returns to the grid. Piano Roll reaches its toolbar from Edit+Up → Grid / Zoom / Recording. Settings rows are directly navigable. FX Edit+Up opens the selected slot, preserving other slots, note data and controls. Chord popovers start on the chord list; held Edit+Left/Right browses, and releasing Edit permits navigation to actions. Non-offset FX cannot be silently replaced by Offset through an incremental value edit.

Regression coverage exercises the configured roles, held Shift across hierarchy changes, dialog modifier lifetime, stick-edit release, direct pitch/octave changes, actual toolbar focus and the menu/FX routes. Native keyboard/pointer checks verify the rendered menu, Mixer/Quick Jump return, hierarchy, Settings and contextual FX screens. These checks do not establish physical button-event delivery or physical controller latency.

## Remaining release gates

External MPE profile, allocation, wire-ordering and Runtime batching contracts pass deterministic tests. Complete native feature parity, physical controller/MIDI/MPE/clock coverage and latency, feedback timing beyond the measured grid/Piano/Drum/Expanded/Minimap navigation, single-note Piano selection, selected Piano resize/transpose and Drum hit-edit paths, complete native Tracker automation, and visual acceptance against Figma remain release gates. Deterministic tests and headless rendering do not certify physical devices, latency or UI outcomes.

`make workload` compares every emitted event across two exact scheduling partitions for 10,000 cycles, with 16 tracks and 64 simultaneous voices. It records raw timings, event counts, toolchain and both source fingerprints under `target/workload/`. This measures the pure scheduler; use Synth's existing native/physical performance suite for audio and painted feedback. A run with concurrent source changes is marked and must be repeated before release.

`make audio-workload ARGS="--seconds 1800 --strict"` renders 30 minutes of integrated Tracker audio through the production application host, workers, queues and Synth DSP. It sustains four real Braids voices on each of 16 tracks, with owned expression, chorus inserts and reverb/delay sends; Stop must leave zero voices. The output adapter runs faster than real time and opens no audio/MIDI device. Reports include raw callback timings, Rust allocation/free counts, per-track audibility, safety counters, late-event count, maximum delivery lateness in frames, producer-sampled queue occupancy peak and both repository fingerprints. Concurrent consumption can make the sampled queue peak lower than its instantaneous maximum. Strict mode requires zero callback deadline misses and p99 below 70% of the 256-frame/48-kHz deadline. A missing/incomplete measurement, failed safety check or source change fails the wrapper. This is rendered-audio coverage, not a wall-clock soak, physical latency test or native C/C++ allocation audit.

`make audio-workload ARGS="--workload mixed --seconds 1800 --strict"` runs the same production boundary with 16 tracks, an initial 64-voice hold, then mixed divisions, dense bend points, retriggers, repeated live phrase edits, view changes and monitor cancellation. Monitoring enters at Runtime's accepted-packet queue; this does not prove physical ingress. The wrapper rejects missing edit, monitoring, dense-attack or lateness evidence. Owned expression combined with chord expansion or retrigger on the same event currently rejects explicitly; the admitted fixture uses separate events for those paths.

`make native-feedback` builds and runs the optimized macOS app bundle as an interactive native witness, retaining its application identity and resources for native UI drivers. Load Example, start playback, make at least 100 changed keyboard grid actions (W/A/S/D), then close the window. The report preserves raw correlated samples and both source fingerprints; stale identities, invalid geometry, missing/coalesced actions, source changes or p95 at/above 50 ms fail. `ARGS="--verify-only /path/to/measurement.json"` independently checks an existing raw report. This measures native input/event receipt through a matching double-animation-frame acknowledgment, including return IPC. It excludes physical input latency, GPU presentation and display scanout. The default grid surface covers Song, Chain and step Phrase. `ARGS="--surface piano"` instead requires 100 native Piano Roll time/pitch cursor actions during playback; grid samples cannot satisfy that gate. Schema 2 records exact focus identity and checks complete action accounting; the verifier still accepts historical schema-1 grid reports. `ARGS="--surface drum"` independently measures the native Drum step/lane cursor, including exact pitch and output identity. `ARGS="--surface drum_edit"` requires independent native hit insertion/removal/Undo/Redo evidence, checking exact event IDs and the visible cell state. `ARGS="--surface piano_selection"` measures single-note selection among overlapping notes and rejects source-changing actions. `ARGS="--surface piano_edit"` independently measures edits to selected stored Piano notes. Every selected note must be visible and unobscured; identity, exact timing, duration, pitch, attack/release velocity and painted note geometry must match. Only a changed source revision and changed selected-note content count. Native coverage includes two-note resize and transpose Undo/Redo. `ARGS="--surface timeline"` separately requires at least 50 native keyboard playback actions in each of Expanded and Minimap, with p95 below 50 ms in each view. It checks exact occurrence and phrase identity; Expanded additionally checks the displayed row time, source row and all six cell values. Selection-range changes and Synth parameter edits remain outside these gates. It requires an operator or native UI driver; it is not the complete automated acceptance journey.

`cargo test -p crest-tracker-app synth::witness:: -- --ignored --test-threads=1` runs the integrated demo, file lifecycle and retained-take navigation witnesses as well as the short audio workload. Use the paired Cargo override as in `make test` until the Synth revision is published. CI runs these witnesses in release mode.

CI defines pure core, host, static and macOS package gates. The historical Git pin and lockfile still require an available committed Synth revision containing these APIs. `make check-pinned` is therefore an open gate, not a passing clean-checkout claim. No commits or pushes were made during this implementation.

## Recording and recovery

Select the physical input through Tracker Settings → MIDI INPUT & CONTROLLER BUTTONS, which opens Synth’s original settings page. For MPE, declare that exact source, lower/upper zone and member/master bend ranges in Tracker Settings. Choose a supported destination in Record setup. Release keys and pedals before Record or external Start/Continue; pre-roll controller state is retained. Ordinary MIDI remains channel-wide. The Braids profile rejects unknown controls, unsupported zone changes and pitches outside its native interval rather than flattening or clamping expression.

Piano Roll exposes Record Setup and Edit Notes sheets, exact note selection, owned member/master expression lanes and raw point editing. Raw MIDI event and point pickers use 64-item pages with absolute point indices; every event and point remains reachable. Duplicate, Paste, range selection, chord application and new raw events use the exact Piano cursor. Expression sequence values retain the domain’s safe-JSON integer limit; exhaustion leaves the form open. Record Setup links to the original Synth input settings and keeps missing-input errors visible.

Arm binds the selected phrase occurrence and freezes its loop length; navigation cannot change the external Start/Continue boundary. Recording and interruption transitions update the application status as well as the capture header. Record loops it while other tracks advance. End Take closes the captured lifetime and commits at a loop boundary; Stop retains an interrupted draft. Commit and Save Take As New Phrase preserve one-step Undo. Save finalizes at the exact cutoff before writing the composite document. Recovery in Settings shows checkpoint time, saved baseline and draft counts before restoring the exact baseline and staying stopped; reconnect never rearms automatically.

Collect Assets creates a `.crest-songpack` directory containing `song.crest-song` and verified resource blobs. Move the whole directory. Missing resources require Locate or explicit Replace; cancellation preserves the current Song. File dialogs and prompts share the same controller navigation and character-entry path.

For an external MPE destination, configure lower/upper zones in Settings → External MIDI Output, then select that connected destination in Record setup. The receiver must support MPE 1 master/member bends, RPN 0 ranges, pressure, CC74 and sustain, and retain released-voice expression across member/master channel reuse. Independent master groups need separate zones; exhausted zones reject without stealing. MIDI 1 cannot selectively cancel an already-ended tail after another source reuses its channel. Global Stop cleans all touched zones. Internal MPE currently requires the declared Braids profile; unsupported engines reject explicitly.

MIDI control mappings target Tracker button actions. Note On with positive velocity presses; Note Off releases. CC values below 64 release and values at or above 64 press once until released. These are button mappings, not absolute knob automation. Unmapped packets remain performance input. In Synth view, use Synth's existing navigation controls or map a button to return to Song.

## Non-negotiable starting points

- One Song is the complete document. New/Open replaces it; Save/Save As preserves it. There is no parent container, song list, child-song management or song switching inside a document.
- Sound definitions remain reusable library resources. The Song pins its saved sound revision until explicit update; installed use, MIDI subscription, routing and mix stay local.
- Crest Synth is the source dependency and working base, with all existing functionality and its actual UI/audio rendering preserved in the integrated application. Both repositories are edited locally without a publish cycle; clean builds pin a Synth revision. Tracker domain code never imports Synth or owns its instruments, voices, DSP, mixer or renderer internals.
- One common timed NoteData representation drives Tracker, Piano Roll, Drum, Euclidean and Random forms. Phrase MIDI FX belong in the first playable slice.
- Piano Roll captures raw timing and MPE expression; input routing stamps explicit event targets. Gamepad editing and reversible quantize preserve expression ownership.
- Phrase-grid events select an instrument directly or an endpoint/MIDI channel. No hidden track route or phrase-settings instrument selector.
- Independent occurrence cursors share exact musical time. Rhythmic divisions through 1/64, subdivisions and meters are not a 64-channel requirement.
- Song, Expanded and Minimap are projections of the same shared chains and phrases; no second pattern model.
- Scale-aware entry/generation is the default. Notes/Intervals changes display only. Explicit chords retain their chosen quality and pitches.
